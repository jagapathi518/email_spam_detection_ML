How It Works

SpamGuard AI uses a combination of machine learning and rule-based heuristics to analyze email text for spam and phishing indicators.

Step 1: Text Preprocessing

When you submit an email, the subject and body are combined and standardized. This includes converting to lowercase, removing HTML tags, normalizing whitespace, and replacing URLs, email addresses, and phone numbers with special tokens. This ensures the model sees a clean, consistent input.

Step 2: Tokenization

The standardized text is split into words (tokens) and converted to numeric IDs using a vocabulary built during training. Words not in the vocabulary are mapped to a special "unknown" token. The sequence is padded or truncated to a fixed length.

Step 3: ML Model Prediction

The token IDs are fed into a neural network with three layers:

  • Embedding layer: Converts each token ID into a dense vector that captures semantic meaning.
  • Global Average Pooling: Averages all token vectors into a single fixed-size representation of the entire email.
  • Dense layers: Transform the representation into a single score between 0 and 1.

This architecture was chosen for its small memory footprint (fits within 512 MB RAM) and fast inference speed, while still providing strong text classification performance.

Step 4: Threshold Application

The raw model score is compared against two thresholds (chosen on a validation set to minimize false positives on legitimate email):

  • Above the spam threshold: Classified as "Likely Spam"
  • Below the not-spam threshold: Classified as "Likely Not Spam"
  • Between the thresholds: Classified as "Uncertain" — the model is not confident enough to make a clear call

The "uncertain" band is intentionally designed to reduce false positives. It is better to say "uncertain" than to incorrectly flag a legitimate email as spam.

Step 5: Heuristic Signals

Separately from the ML model, a set of pattern-matching rules check for common spam/phishing indicators:

  • Urgency language ("act now", "limited time")
  • Prize or financial claims ("you have won", "claim your prize")
  • Credential requests ("verify your account", "enter your password")
  • Suspicious URL patterns (IP-address hosts, URL shorteners, punycode)

These signals are clearly labeled as "heuristic" and are independent of the ML prediction.

Why Train with TensorFlow but Serve Without It?

TensorFlow is a powerful but large framework (~400 MB). In production, we only need the trained weights and a simple forward pass. By reimplementing the forward pass in NumPy (about 20 lines of math), we dramatically reduce memory usage and startup time — critical for a free-tier server with 512 MB RAM.

A "parity gate" verifies that the NumPy implementation produces identical results to the original Keras model on the full test set.

Limitations

  • The model is trained on the Apache SpamAssassin corpus from the early 2000s and may not recognize modern phishing patterns.
  • Only text content is analyzed — not headers, attachments, SPF/DKIM/DMARC, or sender reputation.
  • The model score is not a calibrated probability.
  • This tool does not guarantee that an email is safe.
